# Repository tooling

Use Node 24.14.0, native pnpm 12.16.1 and TypeScript 6.0.3. Run `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm check`, then `pnpm test`. Tests cap Vitest at two workers. Strict checking covers source, tests, authored type fixtures, build helpers and configuration. Suppressions require individual durable reasons; unused suppressions fail.

`pnpm build` emits ESM/CJS runtime files and matching `.d.ts`/`.d.cts` rollups. `pnpm check:api-report` checks the reviewed root signature and the complete generated page set. `pnpm build:docs` explicitly accepts report/documentation updates. Input `dist/index.d.ts` is separate from the published rollup. Real packed consumers verify both module and declaration routes.

Independent `check:changesets` rejects parsed major intent. `check:versions` checks valid full 0.x SemVer in nonprivate source manifests and every actual planned release, including private/inferred/type-none/prerelease releases. Private source metadata alone is exempt. Only the maintainer removes the stability policy; there is no override. The pinned Changesets CLI 3.0.3 and matching planner APIs work from present inputs without Git eligibility. `version:packages` is an explicit local version preparation command with a lock-only refresh; ordinary checks never repair inputs.

CI runs on every branch push and pull request, but not on tag pushes. It has read-only authority, independent visible changeset, version and map checks and build/check/test. `test:ecosystem-map` pins the canonical ecosystem map (version 4), byte for byte. Formatting deliberately excludes AGENTS.md so those bytes cannot be rewritten.

Releases flow through Changesets. Every push to main runs the Release workflow (`release.yml`) in three jobs that use the `changesets/action` sub-actions, pinned by full commit SHA. `select-mode` (`contents: read`, no OIDC) decides whether the commit versions, publishes or does nothing. While changesets are pending, `version` (`contents` and `pull-requests` write) opens or updates a "Version Packages" pull request by running `pnpm version:packages`, which rewrites the version and `CHANGELOG.md` (through `@changesets/changelog-github`, using the action's `GITHUB_TOKEN`) and refreshes the lockfile. Merging that pull request leaves no pending changesets and an unpublished version, so `publish` (environment `npm`, `contents: write`, `id-token: write`) runs `pnpm release`: build, check, test, the 0.x gates, `node scripts/publishing.ts guard`, then `changeset publish`. The action reads the file in which the Changesets CLI records each published package, pushes a `v<version>` tag and creates a GitHub Release from the matching `CHANGELOG.md` section. No permission is granted at workflow level, and only `publish` receives OIDC. The guard authorizes only a push to main of mike-north/sh-codemod inside the workflow's OIDC environment and refuses any npm token fallback; `check:publishing` verifies the workflow keeps that shape. Native npm >=11.5.1 on Node 24 handles OIDC. [Official npm documentation](https://docs.npmjs.com/trusted-publishers/) distinguishes authentication from provenance: this repository makes no provenance claim. The workflow file name and environment are the identity npm trusted publishing is registered against; changing either stops publication.

Trust registration and first publication happen outside this repository and are not verified by its tests. Existing setup helpers are not part of validation. Tests use only local fake registry/upload clients; real packing and empty-cache consumers establish packaging behavior, not working external OIDC.
